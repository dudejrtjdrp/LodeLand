# 스프라이트 아틀라스 패킹 & 텍스처 예산

## 1. 크기 규칙

- **2048×2048 이하**를 기본으로. 모바일/구형 GPU 호환 하한선이다. 고사양 전용이면 4096까지.
- **2의 거듭제곱**이 안전하다. 필수는 아니지만 밉맵·압축·일부 드라이버에서 유리하다.
- 한 장을 억지로 키우기보다 **카테고리별로 나눈다**: enemies / deco / ui / fx. 동시에 화면에 뜨는 것끼리 묶는 게 배치 효율에 좋다.
- 대형 FX 프레임(256~512px × 10~16장)은 아틀라스에 넣지 말고 **독립 시트**로 둔다. 한 장이 아틀라스를 다 먹는다.

## 2. 패딩과 블리딩

- 프레임 사이 **2px 이상 패딩(extrude)**. 필터링/부동소수 오차로 옆 프레임 픽셀이 새어 들어오는 것("가장자리 이물질", 금색 띠 같은 1px 오염)의 원인이 이것이다.
- 픽셀아트는 NEAREST 라 이론상 새지 않지만, 스케일이 정수배가 아니면 샌다. **패딩은 항상 넣는다.**
- 투명 배경 패딩보다 **가장자리 색을 확장(extrude)** 하는 편이 더 안전하다.

## 3. 트림(trim) 금지 조건

패커의 자동 트림은 공간을 아끼지만 **프레임의 원점을 바꾼다.**

트림하면 안 되는 것:
- 애니메이션 프레임 (프레임마다 다르게 잘려 스프라이트가 떤다)
- 히트박스/오프셋이 프레임 좌표에 의존하는 것
- 회전시켜 쓰는 방향성 이펙트

트림해도 되는 것: 정적 UI 아이콘, 배경 장식.

원칙 — **애니메이션이면 트림하지 않는다.** 공간보다 정확성이 싸다.

## 4. 프레임 명명 규약

일관된 규약이 없으면 `generateFrameNames` 가 조용히 빈 애니메이션을 만든다.

```
<원본텍스처키>/<프레임번호>     예: goblin_walk/0, goblin_walk/1
```

- 번호는 0부터, 제로패딩 여부를 통일 (`0` 과 `000` 을 섞지 말 것)
- 원본 파일명을 키에 그대로 남긴다. 나중에 어디서 온 프레임인지 추적 가능해진다
- 애니메이션 키와 텍스처 키를 구분한다 (`fx-nova-fire` = 텍스처, `fx-nova-fire-play` = 애니메이션)

## 5. 텍스처 유닛 / 드로우콜

성능의 진짜 병목은 파일 크기가 아니라 **한 프레임에서 참조하는 서로 다른 텍스처 수**다.

- GPU 텍스처 유닛은 보통 8~16개. 넘으면 배치가 끊기고 드로우콜이 배로 뛴다.
- 뎁스가 섞이면 배치가 깨진다: `[적A][이펙트][적B]` 순으로 그려지면 텍스처가 3번 바뀐다. **같은 텍스처끼리 뎁스를 묶는다.**
- 텍스트가 의외로 비싸다. 동적 `Text` 객체는 각자 텍스처를 만들어 유닛을 먹는다 — 자주 바뀌는 숫자는 **BitmapText** 로.
- 회색조 시트 1장 + 런타임 틴트로 원소별 변형을 커버하면 텍스처 수가 1/N 로 준다.

## 6. 검증

패킹 후 반드시 확인:

- [ ] 매니페스트의 프레임 수 == 실제 시트 프레임 수
- [ ] 마지막 줄의 빈 칸이 완전 투명
- [ ] 애니메이션 재생 시 떨림/점프 없음 (트림 사고 확인)
- [ ] 가장자리 이물질 없음 (패딩 확인)
- [ ] 아틀라스 폭이 한계 이하
- [ ] 인게임 스크린샷 (에디터 미리보기는 스케일이 다르다)

## 7. 흔한 사고

| 증상 | 원인 |
|---|---|
| 스프라이트가 프레임마다 미세하게 튄다 | 트림된 아틀라스 |
| 가장자리에 다른 색 1px 띠 | 패딩 없음 / 비정수 스케일 |
| 애니메이션이 조용히 재생 안 됨 | 프레임 명명 불일치, 제로패딩 |
| 마지막 프레임이 이상한 그림 | 매니페스트 프레임 수 > 실제 |
| 후반부에 갑자기 렉 | 텍스처 유닛 초과, 오프스크린 오브젝트 누적 |
| 흐릿함 | NEAREST 미적용, 또는 업스케일된 소스 |
