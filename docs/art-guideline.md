> 2026-09-01 아트 통일 감사에서 나온 규칙을 고정한 문서.
> **에셋을 새로 추가하거나 색을 만질 때 이 문서를 기준으로 판단한다.**
> 판단이 갈리면 "이미 화면에 있는 것과 같아 보이는가"가 최종 기준이다.

## 1. 팔레트

기준 정의는 `src/ui/theme.ts` 의 `UI` 상수 하나뿐이다. **CSS 문자열이나 0x 숫자를 코드에 직접 박지 않는다.**

### 1.1 베이스 (강철 · 담금 청)

| 역할 | 토큰 | 값 |
|---|---|---|
| 화면 바탕 | `UI.bg` | `#101317` |
| 패널 | `UI.panel` / `panelTop` / `panelDark` / `panelInset` | `#171b20` 계열 |
| 프레임 기본 | `UI.goldDim` (강철) | `#53616d` |
| 프레임 강조·호버 | `UI.goldBright` (담금 청 밝음) | `#8fc3d8` |
| 본문 텍스트 | `UI.text` / `textDim` / `textFaint` | `#dfe6ea` / `#8d9aa5` / `#5c6a75` |

> **주의**: `UI.gold*` 라는 이름은 예전 금색 시절의 잔재다. 실제 값은 담금 청이다.
> 진짜 금색이 필요한 곳(정철·값어치)은 `UI.goldText` / `UI.straw` 를 쓴다.

### 1.2 의미색 — 이 6개 외의 색을 새로 만들지 않는다

| 의미 | 토큰 |
|---|---|
| 화로(체력) | `UI.hpRed` `#d9702e` |
| 쇳밥(경험치) | `UI.xpGold` `#aeb9c2` |
| 정철(골드) | `UI.goldText` `#d9a83c` |
| 위험·피해 | `UI.redN` `#d95f4d` |
| 좋음·이득 | `UI.greenN` `#84b04a` |
| 정보·선택 | `UI.quench` `#6fa7bd` |

### 1.3 등급색 · 원소색

`RARITY_THEME` (6등급) 과 `ELEMENT_THEME` (8원소) 이 유일한 출처다.
등급색은 **검·카드·처치 파편**에서 같은 값을 써야 한다 — 카드에서 본 보라가 처치 파편에서 다른 보라면 등급이 읽히지 않는다.

| 쓰이는 곳 | 참조 |
|---|---|
| 레벨업 카드 밴드·테두리 | `RARITY_THEME[id].num` |
| 검 아이콘 테두리, 도감 슬롯 | `RARITY_THEME[id].num` |
| **처치 파편 색** (§4) | `RARITY_THEME[id].num` |
| 오라·원소 칩·상성 표기 | `ELEMENT_THEME[el].num` |

## 2. 픽셀 스케일

**1픽셀의 크기가 화면 안에서 두 종류를 넘지 않게 한다.**

| 대상 | 원본 px | 화면 배율 | 결과 |
|---|---|---|---|
| 적 유닛 (Tiny Swords) | 100 (lancer 160) | `size.width / 100` ≒ 0.26~1.5 | 카탈로그 `size` 가 곧 히트박스 |
| 바닥 타일 | 64 | 1.0 | `tileSize = 64` 고정 |
| 검 스프라이트 | 32 | ~1.0 | |
| Flat UI | 나인슬라이스 | `UI_PX = 2` | **2배 고정 — 다른 배율 금지** |
| 마을 NPC(에다) | 110 | ~0.9 | |

규칙:

1. **필터는 NEAREST.** 픽셀아트 텍스처는 전부 `Phaser.Textures.FilterMode.NEAREST`.
   `main.ts` 의 `pixelKeys` / `themePixelKeys` / `fxDecoKeys` 목록에 새 키를 추가하는 것을 잊지 말 것.
   (텍스트·글리프만 LINEAR 유지 — 부드러운 윤곽이 유리하다)
2. **`roundPixels: true` · `autoRound: true`** 를 끄지 않는다 (서브픽셀 스미어 방지).
3. **UI 는 2배 고정.** 좁은 화면 대응은 배율이 아니라 `createUiRoot`(디자인 830px 기준 스케일 루트)로 한다.
4. 새 시트를 자를 때는 **캐릭터가 프레임의 60% 이상을 차지하도록** 크롭한다.
   Tiny Swords 원본은 192px 프레임에서 캐릭터가 ~40%뿐이라 (46,38)에서 100×100 으로 잘라 쓴다.
   이 규격을 어기면 히트박스(=`displaySize`)와 보이는 크기가 어긋난다.

| 계층 | 아웃라인 | 근거 |
|---|---|---|
| 적·플레이어 스프라이트 | 원본 시트의 어두운 1px 외곽선 그대로 (덧그리지 않는다) | Tiny Swords·pack2 둘 다 자체 외곽선이 있다 |
| 지형 장식(나무·바위·프롭) | 원본 그대로 + 맵 테마 틴트 | |

## 4. 틴트 규칙

**틴트는 곱연산이다.** 밝은 색으로 틴트해도 원본보다 밝아지지 않고, 원본의 색조가 남는다.

1. **베이스 중립화 원칙** — 틴트를 쓸 소재는 회색/무채색 베이스여야 한다.
   Flat UI 팩은 `scripts/recolor-flat-ui.py` 로 중립 회색으로 재염색해 두었기 때문에 `setTint` 가 의도대로 먹는다.
   **채색된 원본에 틴트를 얹어 "다른 유닛"을 만들려 하지 말 것** — 어둡게만 될 뿐 구분되지 않는다.

2. **같은 시트를 공유하는 적은 반드시 두 축으로 구분한다.**
   - ① **채도 있는 틴트** (연한 파스텔 금지 — `#7fd4e8` 처럼 흐린 값은 원본과 안 갈린다)
   - ② **머리 위 마커** — `EnemyDefinition.marker = { icon, color }`.
     `ui/theme.ts` 의 글리프 키(`g-*`)를 쓰고, 16px 로 적 머리 위 `y - displayHeight*0.62` 에 붙는다.
     본체와 같은 컬링을 따르며, 풀 재사용 시 자동으로 숨는다.

   현재 마커를 쓰는 적:

   | 적 | 공유 시트 | 틴트 | 마커 |
   |---|---|---|---|
   | 결집 사수 `volley-marksman` | `ts-blue-archer` (Needle Queen 과 공유) | `#4fb8d9` | `g-eye` `#8fe4f5` |
   | 장막 소환수 `veil-caller` | `ts-black-monk` (Rustbanner 와 공유) | `#8b6ce0` | `g-el-void` `#c3aef8` |

3. **어픽스 틴트는 등급/역할 틴트를 덮지 않는다.**
   정예·중간보스·보스는 어픽스 색으로 물들이지 않는다(`EnemyManager.applyAffixes`) — 등급 실루엣이 우선이다.
   일반 몹만 첫 어픽스 색으로 물들고, 그 색은 `affixTintColor` 로 저장돼 **처치 파편 색으로 재사용**된다.

4. **검 도트에는 틴트 금지.** 통합 시트의 원색이 곧 아트다 (레벨업 카드·상점·도감 전부 동일).

## 6. 처치 연출 등급 (2026-09-01)

색은 §1.3 의 등급색을 그대로 쓴다. 구현은 `VisualEffectsSystem.enemyDeathFX`.

| 등급 | 조건 | 연출 | 색 |
|---|---|---|---|
| 0 일반 | 그 외 전부 | 금빛 점 하나 (기존 그대로) | `#ffd166` |
| 1 정예 | `isElite` · `isMiniboss` · 어픽스 보유 | 등급색 파편 버스트 + 링 2겹 + 파편 선분 4 | 정예 `rare` · 중간보스 `epic` · 어픽스 몹은 그 어픽스 색 |
| 2 보스 | `isBoss` | **단계적 붕괴** 0ms 플래시 → 50ms 파편 → 210ms 충격 링 | `legendary` |

- 보스의 50ms 경계는 히트스톱 `bigKillMs = 50ms`( ≒ 3프레임)과 정확히 맞춘다 — 정지가 풀리는 순간 파편이 터져야 "끊고 나서 무너진다"로 읽힌다.
- **모션 줄이기 설정이 켜져 있으면 등급 연출을 접고 점 하나만 남긴다.**
- 정예 버스트는 90ms 간격 제한이 있다 (후반 라운드에 겹쳐 화면이 타지 않게).
- FX 는 **전부 공유 레이어(`fx*`)** 로만 그린다. `add.circle` + 트윈 금지 (핫패스 할당 금지).

## 7. 절대 하지 말 것

- ❌ `add.graphics` 로 HUD·패널·버튼을 절차적으로 그리기 → Flat 팩(`ui/theme.ts`)만 쓴다.
- ❌ 새 색 상수를 파일 안에 직접 선언 → `UI` / `RARITY_THEME` / `ELEMENT_THEME` 에 추가한다.
- ❌ 처치·피격 연출에 `add.circle` + 트윈 → `fxRing` / `fxDot` / `fxBurst` / `fxPoly` 를 쓴다.
- ❌ 부유 숫자에 `Text` → `ui/damageFont.ts` 비트맵 폰트.
- ❌ 우하단 피해 로그 패널 재추가 (성능 회귀 이력).
- ❌ `visible` 을 생존 판정에 사용 (화면 밖 컬링용이다).
- ❌ 채색된 원본에 파스텔 틴트만 얹어 새 적 만들기 → §4.2.

## 8. 감사 이력 — 2026-09-01

| # | 발견 | 심각도 | 조치 |
|---|---|---|---|
| 1 | 하단 스킬 HUD 라벨(`SPACE 귀소`)이 아이콘 간격(56px)보다 넓어 옆 칸 글자와 겹침 | 높음 | 라벨을 동작 이름만으로 줄이고, 키는 위쪽 별도 배지로 분리 (리맵·패드 글리프 반영) |
| 2 | 결집 사수·장막 소환수가 원본 유닛(Needle Queen·Rustbanner)과 구분되지 않음 — 파스텔 틴트가 채색 원본에 묻힘 | 높음 | 틴트 채도 상향 + 머리 위 마커 도입 (§4.2). 규칙을 이 문서에 고정 |
| 3 | 처치 연출이 등급과 무관하게 동일(점 하나) — 정예/보스를 잡은 감각이 없음 | 높음 | 등급 3단 연출 (§6) |
| 4 | 마을 시설 이름표가 밝은 바닥에서 대비 부족 | 중간 | 월드 위 텍스트 그림자 규칙을 §3 에 고정 |
| 5 | `UI.gold*` 토큰명이 실제 색(담금 청)과 불일치 — 새 코드가 잘못 고름 | 낮음 | §1.1 에 명시 (개명은 호출부가 많아 보류) |
| 6 | 등급색이 카드/도감에만 쓰이고 인게임 연출에는 안 쓰임 | 중간 | 처치 파편에 `RARITY_THEME` 재사용 (§1.3 · §6) |
